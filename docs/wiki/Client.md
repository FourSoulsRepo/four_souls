# Client

The desktop client is React + TypeScript in `frontend/` (ADR 002), with three libraries: Zustand for the store, Motion for animations and drag, nothing else (ADR 008). It keeps the KISS rules of [Frontend tests](Frontend-tests): the server decides, the client draws and sends intents.

## Files

| File | What it does |
|---|---|
| `src/bridge/` | The only code that calls Wails: settings, versions, card data, hosting. |
| `src/net.ts` | The one WebSocket to the game server. |
| `src/protocol.ts` | Message and engine view types, mirroring `internal/protocol` and the engine; `wsURL`, `errorText`. |
| `src/lobby.ts` | Pure: how server messages change the session (screen, lobby, error). |
| `src/playback.ts` | Pure: event → effect mapping, speed, and the update queue. |
| `src/table.ts` | Pure: where each player sits. |
| `src/cards.ts` | Pure: card kinds, text icons. |
| `src/store.ts` | The Zustand store; wires the pure parts to the bridge, the socket and playback. |
| `src/screens/` | One component per screen; `App.tsx` picks by `store.screen`. |
| `src/components/` | `Card`, `CardZoom`, `Board`, `PlayerArea`, `Pile`, `Effects`. |
| `src/fakeBridge.ts` | Dev only: fake Wails bindings for tests (`?fake`). |

## Data flow

1. A server message arrives in `store.receive`.
2. `lobby.onMessage` updates the screen and lobby.
3. An `update` also goes to playback, which queues it.
4. Playback plays the update's events as effects, one at a time (`store.playing`, drawn by `Effects`), then sets `store.game`.
5. The table (`GameScreen`) draws `store.game`; it never changes game state itself.

## Effects

`playback.effectsFor` maps engine events to effects: a flying card (looted, discarded), a dice, a popup (cents, healing), a banner (turn, winner), a revealed card. Effects find their places on screen by `data-zone` attributes: `deck-loot`, `discard-monster`, `player-1`, `hand-0`, `obj-42` and so on, falling back to the next zone when one is not drawn.

An attack hit (a `damaged` event with `text: "combat"` and a `source`) is a lunge (15.3, `components/lunge.ts`). A copy of the source card goes into a layer of its own, `.effects-trail`, so the table never clips it; the card itself is hidden until the copy is back. The copy winds up, goes into the target, and returns; at the hit a starburst "−N" pops on the target. The lunge ends its effect at the hit, so playback shows the update at once and the target's HP drops while the copy returns. The copy loses its `data-zone` and test ids, and the layer is `aria-hidden`, so nothing finds the copy in place of the card. Pending damage (`damage_pending`) has no popup: damage shows when it lands.

Other damage (15.37, `components/marks.ts`) is a `hits` effect: all `damaged` events in a row of one update join it. A glowing shot flies from each source to its target, in the same layer; the source is `obj-<source>`, else the stack row, whose `data-zone` is `stack-src-<source>`. When the shots land, every target bursts at once and the effect ends. A `died` event is a `deaths` effect: a big skull pops on each dying card (a monster by its old ID, `prev`; a player by the character). The effect ends at 60 % of the skull, so the card leaves while the skull fades. `Effects.tsx` starts all three layered effects through one `Layered` component, guarded against Strict Mode's double run.

Damage has sound (15.50, `sounds.ts`), all from Hearthstone, ripped into the Sounds Resource's packs. The lunge plays `attack-hit.mp3` at the hit, WoW's `unarmedparrymetala`. A `hits` effect plays one fireball for all its shots: the Fireball spell's cast (`effect-cast.mp3`) as they leave and its impact (`effect-impact.mp3`) as they land. `App.Sounds()` gives the files from the private images; each URL is empty without them, and that sound stays silent. A file that fails to load, or an autoplay the browser blocks, is silent too. Sounds belong to effects, so they follow the animation speed: with animations off, nothing plays. All files are mono MP3, which WebKitGTK, WKWebView and WebView2 all play.

Health badges get the `hurt` class while the card has damage: a pale heart with a red number (T-25). A hurt monster shows its health badge even when the number matches the print.

A dice effect draws `Die`: one face cut out of the player's dice texture (V-19). `App.Dice` lists the looks with their image URLs, and the `dice` setting picks one. A texture is a 3×3 grid in the Tabletop Simulator layout: the top row is unused, then faces 2 4 5 and 1 3 6 (`dice.ts`). Without a texture, or for a modified value outside 1–6, the die is plain with a number.

## Game mats

The table lies on a mat (ST-03, V-24), drawn by `mats.matLook`. Three color mats are CSS: Green felt, Basement and Cathedral. Image mats come from `App.Mats`, one per file in `assets/mats/`; an image mat with a color mat's id takes its place in the menu, and a new id is added after them. The image is drawn under a dark shade, so cards and text stay readable, and over its colors (Basement for a new id), so a missing or unloadable image leaves the colors. The `mat` setting keeps any mat file name, so a saved mat whose image is gone also falls back to colors. An empty `mat` is the default: the first mat image, or Basement without images (`mats.matOf`). Green felt stays a choice but is never the default: with seat boxes it read as a poker table (H-05).

## Board

`Board` is one framed board in the middle of the table (F-01, H-01). Its grid has six columns: the history strip (H-07), the info column (turn badge, stack, and the full history when open), the monster and shop slots, the bonus souls, the decks, each with its discard (H-16), and the End turn button at the right edge (H-04). Nothing lies over it (F-02); the e2e tests check that every deck and discard is uncovered with 2, 3 and 4 players.

The board has one fixed shape, empty or full (H-06, V-23). `.board-cell` takes the space the players leave and is a size container; the board takes the largest size of its shape that fits there. `--u`, the width of a slot card, sizes everything on it, so no zone grows or shrinks when cards come and go. An empty slot keeps a dashed outline; up to four slots show full size, and more share the row. `--u` is used only outside cards: inside a card, container units would measure the card.

Players sit on the mat with no seat boxes (H-05); the active player's name is in the accent color. Choices open at the bottom edge, over the viewer's own area, so the board and its targets stay in view.

The viewer's own area (`OwnArea` in `PlayerArea.tsx`, 15.17) is a three-column grid: status, character, items, with the hand below. The character has a column of its own, so it stays centered under the board whatever the status and the items take (H-02). The status shows the name, the coins as a big number like Hearthstone's mana (H-18), and for the active player what is left this turn. The character card carries the live health and attack from `PlayerView.hp` and `atk` as big badges (`Card`'s `stats`, H-15). The hand box is shorter than its cards: they hang past the bottom edge, where `.game` clips them, so the box itself stays on screen (H-03). `fan` sets the angle and overlap on the hand from the card count, so a big hand still fits; each card turns by its `--spread` from the middle. A hovered card comes to the front; rising and glow wait for 15.27.

Buy and attack are round icons beside the own status (`TurnActions.tsx`, 15.19, F-11): a column right of the coins, so the status never grows taller than the character card and the board keeps its size. An icon is lit when the update allows its intent and the player may act, dim otherwise (F-12). A press marks the icon at once, until the next update (V-15); while the player picks what to buy or attack, that icon stays pressed (F-13). Keys B and A press them; the listener ignores text fields and modified keys. There is no Cancel: a declared purchase passes priority (R-SHOP-02).

End turn is one big button in the board's last column (`EndTurn` in `TurnActions.tsx`, 15.20, H-04); the column is part of the board's fixed shape, so the board never moves when the button appears. On the viewer's turn it is yellow, and dimmed while the engine does not allow ending the turn yet, e.g. while the stack resolves; on another player's turn it is grey and says "Their turn" (H-19). When the update allows nothing but passing and ending the turn (`TurnActions.idle`), it glows green (H-20); with reduced motion the glow stays still. The button looks like the game's cut-out art: the game's hand-drawn letters, a thick ink outline, a lumpy tilted shape and a hard drop shadow that it sinks onto when pressed. Pass in the stack panel, Skip all in the action bar, and the Buy and Attack icons share the ink outline and shadow. The letters come from `--font-game` in `style.css`: font-souls Title for Latin, then the Russian card font, which the browser uses glyph by glyph for Cyrillic, then the system font. `fonts.ts` registers both faces from `App.Fonts()` URLs; without the private images there are no URLs, no faces, and the system font shows. Keys (`useKey` in `keys.ts`, F-15): E ends the turn, Space passes, as the Pass button does. Keys pressed in a text field, a dialog, or a menu are left alone. Space also never clicks a focused button, so it cannot end the turn by accident.

Opponents (`OpponentArea`, 15.18) show the same facts: a small name outside the board (H-21), coins with the same `Coin`, the soul crystals, the character with its `stats` badges, the items, and the hand as fanned backs (F-07, F-08, H-17). At the top the area mirrors the own area: a three-column grid keeps the character centered over the board, and the hand row is shorter than its backs, so they hang past the top edge, upside down as across a real table. In a side column (`.player-left`, `.player-right`, 150 px) the name comes first, clear of the corner menu, then the hand and the cards at `small` size, two to a row. The narrow columns leave the board more width, so with three players, where the top is free, it grows (F-09). The allowance wraps only between its parts.

The coin by the cents is the game's own coin (15.38): `App.Icons` gives `assets/icons/coin.webp`, the ¢ face cut out of the game's `coin.png` by the tools repo, or no URL when the file is missing; the store keeps it in `store.icons`. `Coin` in `PlayerArea.tsx` draws it, and falls back to the drawn ¢ coin when there is none or it fails to load. The Attack icon works the same way (15.24): `App.Icons` also gives `assets/icons/sword.webp`, the game's 65 px pixel sword (lossless WebP of `assets/sword.png`), drawn with `image-rendering: pixelated`; `SwordIcon` in `TurnActions.tsx` falls back to the drawn sword. Dim, the image is greyed and faded like the drawn icons.

Souls are a column of gem slots left of every character, like Hearthstone's mana crystals (`Souls` in `PlayerArea.tsx`, 15.39, V-30, V-31). `soulSlots` in `table.ts` gives one slot per soul the game needs, `GameView.win_souls`, with the gained ones (`PlayerView.souls`, the soul value) filled from the bottom up; souls past the target add filled slots. A view without `win_souls`, from an older server or record, counts four. The gems are pure CSS (`clip-path` rim and inset), so they look the same without the private images; `--crystal` sets their width, 16 px for the own area and 12 px for opponents. The character cell pads its right side as wide as the column, so the card stays centered.

## Card backs

Face-down cards show their deck's back (V-26). `App.Backs` gives the loot, treasure and monster back URLs from `assets/backs/<kind>.webp`, or no URL when the file is missing; the store keeps them in `store.backs`. `Card` draws the back image, and falls back to the plain dark back with the deck name when there is none or it fails to load. An opponent's hand is `Pile.HiddenHand`: one loot back per card, fanned, at most eight, with the card count, in the `hand-<id>` zone, so drawn cards fly to it. A back never carries a card ref, so it cannot reveal the card.

Effect durations scale with the animation setting (ST-05) and speed up when updates pile up; past 8 waiting updates they are skipped, so the table always catches up. Each effect has a time limit, so a closed screen never blocks playback.

## Cards

`Card` shows a card image, or a blank card with its text when the image is missing (A-11). Sizes: `hand`, `table`, `small`, `zoom`; everything inside scales with the width through container query units. Hover zooms a card; on touch a long press does (B-06). A card with an `objectId` pops in when it first appears and is a `data-zone` for effects.

## Player actions

`actions.ts` turns the update's allowed intents into what the table offers: buttons (pass), the turn actions (attack, buy, end turn), per-card actions (play, use an ability), a choice, or a discard. The table offers nothing else, so it never sends what the server would not allow; a refused intent still shows the engine's reason and rule ID.

* Cards the player may act on glow yellow; clicking or tapping one opens its action menu.
* A playable loot card can also be dragged onto the board (`data-drop="play"`). The drag is plain pointer events with pointer capture (`HandCard` in `PlayerArea.tsx`).
* Aiming (15.25): a click on a card whose one action asks for a target first starts aiming (`store.aiming`, set by `interact`); the next click picks the target. The targets come from the engine: `update.aims` gives the first target options of each allowed play or use, by its index in `allowed` (`Game.Aims` in `aims.go`), so the client computes no rules. While aiming, the targets glow red (`hl-aim`), a hand card stays lifted in the fan, and with a mouse a red arrow runs from the card's middle to the pointer (`AimLayer` in `Aim.tsx`, transform only; the head's tip is at the pointer, the shaft stops at its base). `AimLayer` takes the next click in the capture phase: `zonesAt` and `targetAt` in `aim.ts` find the target under it (a card's `data-zone`, a player area, or a stack row's `data-stack`); a target sends the play and keeps the target in `store.aimed`, and the target prompt that follows picks it at once (`aimedOption` in `actions.ts`). `aimClick` in `aim.ts` decides the click (15.33): the aiming card itself does nothing unless it may target itself, then it picks itself; empty space cancels; and any other card, pile, or stack row that is no target keeps aiming and shows the aim's `reason` from the engine (`targetReason` in `aims.go`) in a note above the click for 2.5 s. A player is aimed at by the character card only: it carries `data-player`, `zonesAt` turns that into `player-N` and leaves out the player areas' own zones, and `interact.character` lights the character instead of the area. A right click, Esc, or a new update cancels. Such cards are not dragged; a card with a mode or no target keeps the menu and the drag.
* Place, then aim (15.34): a card with a mode is dragged onto the board; its mode dialog asks first. The target prompt that follows is aimed, not asked in a dialog: the engine names the card in `view.activating` (only for the chooser), `promptAim` in `aim.ts` turns the prompt into an aim from it (`Aiming.choice` instead of `Aiming.intent`), and `GameScreen` starts it before paint, so the dialog never shows. A pick sends the prompt's option for that target; Esc, a right click, or empty space sends its cancel option (`cancelOption`), and the engine leaves the card in hand. The aim yields to `store.aimed` (a card already aimed at its target picks it at once) and to the dialog when a target or the card is not on the table (`onScreen`). While aiming, player areas offer no pick; the character card is the player's target. A card with no valid target is never offered: the engine refuses it (R-ABIL-06).
* The aiming arrow (15.32, `AimArrow` in `Aim.tsx`, styles in `Table.css`) follows Hearthstone's: a chain of thick red blocks from the card and a big notched head, a little see-through and drawn over everything. The chain is placed once with translate and rotate; `blocks` in `aim.ts` counts how many fit short of the head. The blocks march toward the head (`aim-march`); the first fades in and the last fades out in step, so the loop has no seam. Over a valid target (`targetAt` on every pointer move) the arrow gets `.on`, and a red ring with cross ticks marks the tip. Only `transform` and `opacity` move; the `--march` duration follows the animation speed (`scaleFor`), and speed off or reduced motion stands the arrow still. It is pure CSS, so it looks the same without the card images.
* Choices show as a dialog; card options show as cards (V-07). Options that point at the table (`view.options`, from the engine) glow blue there and can be clicked in place.
* The player acts only on the latest update (`store.behind`) and once per step (`store.sent`); meanwhile buttons stay but are disabled, so nothing blinks.
* A card with two or more activated abilities opens the ability dialog instead of the menu (`AbilityDialog` in `ActionMenu.tsx`, C-05): the card large at the left, one button per ability line at the right. The lines come from the engine: `CardView.abilities` holds each ability's words by the activate intent's `choice`, only on a played card with two or more activated abilities (`playedView` in `view.go`). An index can point at another card's ability (copied tap abilities), so the client cannot read the lines from its own card data. A line the update does not allow stays in the list, greyed, so the card reads in full. Each line looks like a row of card text: parchment with an ink outline, the cost icon boxed at the left (a drawn tap arrow, or "$"), the cost in red ink, then the effect (`abilityLine` in `cards.ts` splits the words at the first colon). Dialogs use the game's letters: titles in `--font-game`, card text and option buttons in `--font-card`, font-souls Body from `App.Fonts().body`.
* On own turn the Buy and Attack icons carry a small paper badge with the purchases and attacks left (`TurnActions`' `left`, from `PlayerView.purchases` and `attacks`); it turns dark at 0. Loot plays left show by the own name as "Loot N". Opponents keep the whole "Loot · Attacks · Buys" line, as they have no icons. Used items stay dimmed, not turned (C-04). Attack-readiness marks (a green frame, "zzz", T-11, H-22) were tried and dropped: they do not suit this game (owner, 15.24).

## Stack and waiting

`stack.ts` has the words: `stackParts` describes a stack item in parts that keep the player, the target and the card apart ("Ann plays A Dime!!", "Attack: Bo rolls 4 against Gaper", "Bo deals 2 damage to Gaper"; damage a player takes names its card, "Boom Fly deals 1 damage to Ann", ADR 011); `stackLine` joins them into plain text. `waitText` says who the game waits for and why ("Your turn", "Bo may respond", "Ann is choosing"). `stackIcon` picks a row's icon and `stackCard` the card it shows on hover.

The stack panel (`StackPanel.tsx`, 15.21) always sits in the board's info column, newest item on top; an empty stack says "Nothing on the stack". Each row is a square icon (cropped card art, a die with the roll, a blood drop with the damage, or a skull) and one line, with players in their seat color (`playerColor` in `table.ts`, also the dot by each name) and targets in red. Hovering a row, or tapping it, shows the card large through the shared zoom with a caption: the used ability's words, highlighted, and the owner. The words come from the engine view: `GameView` fills each stack item's `text` with the ability's text, or the chosen mode's; the game state never holds it. Highlighting on the card image itself is not possible, since the image has no map of its abilities. Pass sits in the panel header; Space presses it.

The action bar shows the response timer from `update.deadline` (N-07) and "Skip all" / "Cancel skip" while something is on the stack (N-06); the server does the skipping. On another player's turn it also offers "Wait for my turn" / "Cancel wait" (`waitTurn` in `stack.ts`, N-16); it is hidden once the turn before the viewer's is ending, since that end window is the last chance to act.

## Info panels

`history.ts` builds the history from the events this viewer received: one entry per resolved stack item (`stack_resolved`), plus turns, loots, rewards, curses and the winner. The server already filters events per viewer, so a hidden loot reads "Bo loots a card". The history lives in `store.history`, grows as playback shows updates, and is lost on leaving the table (replays come in step 10).

The history strip (`HistoryStrip.tsx`, 15.22) is the board's first column: one icon per resolved stack item, newest on top, drawn by the stack panel's `ItemIcon`. The engine's `stack_resolved` event carries the resolved `item`, with its ability's words, so the strip knows its kind and whether it was an attack; `stackBadge` puts a sword on attacks and a bolt on loot plays (H-08). Hovering an icon uses the stack's `itemZoom`. A gold line ends each turn's run of icons. Stack items carry `source_card` and `target_card` from the engine (views and the resolved event fill them while the card is public), so an attack roll names and shows its monster even after it died; an item without ability words shows its line under the zoomed card instead. The engine splits roll texts: a roll result trigger's `text` is only the rolled line (`rollResultText`), and the item that rolls says only the words up to the roll (`rollStartText`, "Roll."), on the stack and in the history; the zoomed card, image or text, shows every result. The scroll button on top opens the full `HistoryPanel` in the info column, under the stack; it starts hidden.

The turn badge shows the turn number, the active player and the step. Player areas show what the engine computed: HP, ATK, cents, souls, hand size, and for the active player the loot plays, attacks and purchases left (`PlayerView.loot_plays`, `attacks`, `purchases`). Every number on a card is a `Badge` in `Card.tsx`: an SVG shape with a thick ink outline, a hard shadow and a slight tilt, and the number in the game's font (`--font-game`), like the End turn button. Health is a red heart, the dice a bone-white die, attack a gold blob. Card counters are a green blob on the card art (`CardView.counters`, C-01); a text card has it in its top corner, clear of the words. A monster's `CardView.stats` holds its live and printed health, dice and attack; `Card`'s `monster` draws a badge only for a value that differs from the print (C-03). The health badge replaces the damage mark on monsters and characters; a card without health keeps the dark-red mark in its top corner. The zoomed card shows no badges, so its words stay readable (owner, 15.23).

## Pause, reconnect, game over

* A lost connection during a game keeps the table (`lobby.lost`); `LostOverlay` offers Reconnect, which says hello again with the seat's token from `welcome`.
* The seat token also goes into the settings (`settings.rejoin`: address, token, game) whenever the player sits at a table. A restarted app sends it on the next connect to that address and lands back in its seat; `seatOf` then reads the seat from the welcome.
* `update.pause` shows `PauseOverlay` to the others: who is away, the votes, and Wait / Go on without them (`vote` messages).
* `view.over` shows `EndOverlay`: the winner and Save record. `App.SaveRecord` (Go, `record.go`) asks where to save and downloads `http://<server>/record?game=…&token=…`; it accepts only such links.

## Save and continue

The in-game **Menu** (`GameMenu`) offers **Save and leave** to seat 1, the host (`save` message), and **Leave game** to all. After `saved`, everyone is back on the server's game list. **Continue a saved game** on the host screen starts the in-app server and shows that list (`store.hostSaved`); **Continue** sends `load`. A loaded table shows its seats as "back" or "not back yet".

## Menu screens

The splash, the main menu and the menu-like screens (`src/screens/`) use the game's letters too (15.40, V-33). Titles and screen headings use `--font-title` from `style.css`: the Russian card font (tboi4s), which has mixed case for Latin and Cyrillic, then the system font. Buttons use `--font-game`, as on the table. Body text, form labels, inputs and the fan-game notice stay in the system font, so they read easily. Headings keep `font-weight: bold` with `font-synthesis: none`: the game font has no bold face and is not faked, while the system font fallback stays bold, as it was before the change. Buttons off the table share the look of the ability lines (15.24): cut-out parchment (`--paper` in `style.css`) with an ink outline, a hard shadow and a slight tilt that alternates; the main action of a screen (`.primary`) is the gold of End turn (`--gold`). One rule in `style.css` covers `.screen button`, `.menu-buttons button`, `.overlay-buttons button` and `.game-menu-button`. Panels and overlay boxes are a dark board with an ink frame; they set their own `--fg` and `--muted`, so they stay dark in the light theme, like the game's dialogs. Inputs and selects are parchment slips with an ink arrow; checkboxes are parchment boxes with an ink tick.
