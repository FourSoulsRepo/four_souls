# Client

The desktop client is React + TypeScript in `frontend/` (ADR 002), with three libraries: Zustand for the store, Motion for animations and drag, nothing else (ADR 008). It keeps the KISS rules of [Frontend tests](Frontend-tests): the server decides, the client draws and sends intents.

## Files

| File | What it does |
|---|---|
| `src/bridge/` | The only code that calls Wails: settings, versions, card data, hosting. |
| `src/net.ts` | The one WebSocket to the game server; `connectFirst` tries `wss://` then `ws://` (ADR 017). |
| `src/protocol.ts` | Message and engine view types, mirroring `internal/protocol` and the engine; `wsURLs` (what a typed address tries, ADR 017), `recordURL`, `errorText`. |
| `src/lobby.ts` | Pure: how server messages change the session (screen, lobby, error). |
| `src/playback.ts` | Pure: event → effect mapping, speed, and the update queue. |
| `src/animations.ts` | Animation claims: which effect brought or showed a card, and clashes ([Animations](Animations)). |
| `src/table.ts` | Pure: where each player sits. |
| `src/cards.ts` | Pure: card kinds, text icons. |
| `src/store.ts` | The Zustand store; wires the pure parts to the bridge, the socket and playback. |
| `src/screens/` | One component per screen; `App.tsx` picks by `store.screen`. |
| `src/components/` | `Card`, `CardZoom`, `Board`, `PlayerArea`, `Pile`, `Effects`. |
| `src/fakeBridge.ts` | Dev only: fake Wails bindings for tests (`?fake`). |
| `src/i18n.ts` | `t()`, the language files and the chosen language ([Languages](#languages)). |
| `src/locale.ts` | Pure: lookup, plural forms, the test language, the language list, the translation checks. |
| `src/locales/` | One JSON file per language; `en.json` is the source; `glossary/` holds the game terms. |
| `src/translations.test.ts` | `make i18n`: the checks on the real files ([Translation checks](#translation-checks)). |

## Data flow

1. A server message arrives in `store.receive`.
2. `lobby.onMessage` updates the screen and lobby.
3. An `update` also goes to playback, which queues it.
4. Playback plays the update's events as effects, one at a time (`store.playing`, drawn by `Effects`), then sets `store.game`. The first update has no table yet: it is drawn first, then its effects play on it; only a game start brings events then (Cain's banner, 15.43).
5. The table (`GameScreen`) draws `store.game`; it never changes game state itself.

## Effects

`playback.effectsFor` maps engine events to effects: a flying card (looted, discarded), a dice, a popup (cents, healing), a banner (turn, winner), a revealed card. Effects find their places on screen by `data-zone` attributes: `deck-loot`, `discard-monster`, `player-1`, `hand-0`, `obj-42` and so on, falling back to the next zone when one is not drawn.

An attack hit (a `damaged` event with `text: "combat"` and a `source`) is a lunge (15.3, `components/lunge.ts`). A copy of the source card goes into a layer of its own, `.effects-trail`, so the table never clips it; the card itself is hidden until the copy is back. The copy winds up, goes into the target, and returns; at the hit a starburst "−N" pops on the target. The lunge ends its effect at the hit, so playback shows the update at once and the target's HP drops while the copy returns. The copy loses its `data-zone` and test ids, and the layer is `aria-hidden`, so nothing finds the copy in place of the card. Pending damage (`damage_pending`) has no popup: damage shows when it lands.

Other damage (15.37, `components/marks.ts`) is a `hits` effect: all `damaged` events in a row of one update join it. A glowing shot flies from each source to its target, in the same layer; the source is `obj-<source>`, else the large played card (`played-<source>`), else the stack row, whose `data-zone` is `stack-src-<source>`. When none of these is on screen, for a card that already left, the shot comes from the player who dealt the damage (`by`, plus 1): their character card, else their area (`damageFrom`, 15.77). A monster's damage has no `by`; its card is its source. Without any of these, only the burst shows. When the shots land, every target bursts at once and the effect ends. A `died` event is a `deaths` effect: a big skull pops on each dying card (a monster by its old ID, `prev`; a player by the character). The effect ends at 60 % of the skull, so the card leaves while the skull fades. A dead monster's `died` also keeps the slot it died in, from the view on screen, by its held object (`diedAt` in the store, cleared on a rollback or leaving): its later `discarded` or `gained_soul` with that `prev` flies it from there to the discard or the player, even after reward rolls in between, and its slot shows empty while it flies (`lifted`, 19.73). `Effects.tsx` starts all three layered effects through one `Layered` component, guarded against Strict Mode's double run.

A `card_revealed` event for a card that is now the top of a monster or shop slot in the update's view is a reveal, then a `place` effect (19.3). The card flies from its deck to the slot, whose `data-zone` is `monster-slot-<i>` or `shop-slot-<i>`, and stays there: it goes into `store.placed`, which `Effects` draws until playback shows the next view. So on a deck attack the monster is in its slot before the attack roll of the same update plays over it. A deck attack reveals its card in one update and puts it in the slot in the next, each with a `card_revealed`; a card the update on screen already revealed skips the large reveal (`seen` in the effect context, 19.4). A `card_revealed` with `prev` is a card a dead or gone top card uncovered (a covered monster, or a room under a Red Key room): it was in its slot already, face up, so it gets no reveal and no `place`; the view draws it and it pops in (19.72).

A reveal grows out of the card's deck (`deck-<kind>`) to the middle (15.73). When the very next effect moves the same card (`fly` or `place`), `holdReveals` sets the reveal's `hold` and the move's `middle`: the reveal ends large in the middle, and `FlyFromMiddle` flies the large card from there to its place, shrinking to a table card. Any other reveal shrinks back onto its deck: a deck attack's card waits there face up (19.9), and a "reveal the top card" leaves it in the deck.

Damage has sound (15.50, `sounds.ts`), all from Hearthstone, ripped into the Sounds Resource's packs. The lunge plays `attack-hit.mp3` at the hit, WoW's `unarmedparrymetala`. A `hits` effect plays one fireball for all its shots: the Fireball spell's cast (`effect-cast.mp3`) as they leave and its impact (`effect-impact.mp3`) as they land. `App.Sounds()` gives the files from the private images; each URL is empty without them, and that sound stays silent. A file that fails to load, or an autoplay the browser blocks, is silent too. Sounds belong to effects, so they follow the animation speed: with animations off, nothing plays. A thrown die plays `dice-roll.mp3` as it first lands (15.69): a plastic die on a wood board, source unknown, so it lives in the private images too. All files are mono MP3, which WebKitGTK, WKWebView and WebView2 all play. Every file is levelled to -20 LUFS over its loudest 200 ms and plays at full volume (ADR 022; how to check one: [Card data tools](Card-data-tools)).

Health badges get the `hurt` class while the card has damage: a pale heart with a red number (T-25). A hurt monster shows its health badge even when the number matches the print.

A dice effect draws `Die`: one face cut out of the player's dice texture (V-19). `App.Dice` lists the looks with their image URLs, and the `dice` setting picks the player's own, sent in hello. The ten looks are the d6 of the holy and unholy sets; Settings groups the ones with a texture by set (`diceChoices`) and previews the six faces, and shows no field without the images (15.64). Every die is drawn in its roller's look, from the seats of the update (`diceImage`, 15.6): the throw, the landing die, the stack's roll icons and the last roll. A seat without a look, as a bot's, gets the default; a look this app does not have is plain. A texture is a 3×3 grid in the Tabletop Simulator layout: the top row is unused, then faces 2 4 5 and 1 3 6 (`dice.ts`). The textures are upside down, so `faceStyle` turns the shown face half a turn about its own middle. Without a texture, or for a modified value outside 1–6, the die is plain with a number. Every die has a bevel of light and shade (`Die.css`, 15.69): each `.die` is a size container, so the inset shadows scale with it. A thrown die is a `DieCube`: six faces (`cubeFaces`, value on top, opposite faces adding up to seven) turned in 3D with `preserve-3d`, each face half a die (`50cqi`) from the middle. Cube faces are square, with no round corners, so they meet edge to edge (19.40). Playwright's headless WebKit draws 3D transforms flat, so its screenshots show one face; Chromium shows the cube. It rests seen from above (15.82): the value's top face fills most of it, and the front and right sides show as strips; static shades per face fake the light from above. A roll of several dice (Classic Roller, Mutant Spider, Cursed Lil Haunt) carries every die in `dice_rolled`'s `dice`; the throw drops them all in a row at small uneven gaps (`diceDelays` in `dice.ts`), each die clatters as it lands, and the throw ends with the last (19.39).

## Game mats

The table lies on a mat (ST-03, V-24), drawn by `mats.matLook`. Two color mats are CSS: Basement and Cathedral. Image mats come from `App.Mats`, one per file in `assets/mats/`; an image mat with a color mat's id takes its place in the menu, and a new id is added after them. The image is drawn under a dark shade, so cards and text stay readable, and over its colors (Basement for a new id), so a missing or unloadable image leaves the colors. The `mat` setting keeps any mat file name, so a saved mat whose image is gone also falls back to colors. An empty `mat` is the default: the first mat image, or Basement without images (`mats.matOf`). Green felt was a third color mat until 15.81 (ST-08): it read as a poker table (H-05). A saved `felt` is the default now, in Go's `Load` and in `matOf`.

## Board

`Board` is one framed board in the middle of the table (F-01, H-01). Its grid has six columns: the history strip (H-07), the info column (turn badge, stack, and the full history when open), the monster and shop slots, the bonus souls, the decks, each with its discard (H-16), and the End turn button at the right edge (H-04). Nothing lies over it (F-02); the e2e tests check that every deck and discard is uncovered with 2, 3 and 4 players.

The board has one fixed shape, empty or full (H-06, V-23). `.board-cell` takes the space the players leave and is a size container; the board takes the largest size of its shape that fits there. `--u`, the width of a slot card, sizes everything on it, so no zone grows or shrinks when cards come and go. An empty slot keeps a dashed outline; up to four slots show full size, and more share the row. `--u` is used only outside cards: inside a card, container units would measure the card.

Players sit on the mat with no seat boxes (H-05); the active player's name is in the accent color. Choices open in the middle over the dimmed table, with big cards (15.29, H-11); "View board" hides one to look at the table (F-20).

The viewer's own area (`OwnArea` in `PlayerArea.tsx`, 15.17) is a three-column grid: status, character, items, with the hand below. The character has a column of its own, so it stays centered under the board whatever the status and the items take (H-02). The status shows the name, the coins as a big number like Hearthstone's mana (H-18), and for the active player what is left this turn. The character card carries the live health and attack from `PlayerView.hp` and `atk` as big badges (`Card`'s `stats`, H-15). The hand box is shorter than its cards: they hang past the bottom edge, where `.game` clips them, so the box itself stays on screen (H-03). `fan` sets the angle and overlap on the hand from the card count, so a big hand still fits; each card turns by its `--spread` from the middle. The ends drop at most `fanDrop` (24 px), so even a hand of 12 keeps every card's top in reach (19.15). A hovered card comes to the front and its zoom rises from it (15.27, H-13). A hand card the player may play or use glows green instead of yellow (H-12); it keeps the `hl-act` class, so tests find it as before. The glow is Hearthstone-like, not a ring: a thin light rim and a faint inner light on the card (`::after`), and behind it, drawn by its fan slot (`.hand-card.usable`), a tight bright halo and a wide soft aura that breathes by opacity (`hand-glow`).

Buy and attack are round icons beside the own status (`TurnActions.tsx`, 15.19, F-11): a column right of the coins, so the status never grows taller than the character card and the board keeps its size. An icon is lit when the update allows its intent and the player may act, dim otherwise (F-12). A press marks the icon at once, until the next update (V-15); while the player picks what to buy or attack, that icon stays pressed (F-13). Keys B and A press them; the listener ignores text fields and modified keys. There is no Cancel: a declared purchase passes priority (R-SHOP-02).

End turn is one big button in the board's last column (`EndTurn` in `TurnActions.tsx`, 15.20, H-04); the column is part of the board's fixed shape, so the board never moves when the button appears. On the viewer's turn it is yellow, and dimmed while the engine does not allow ending the turn yet, e.g. while the stack resolves; on another player's turn it is grey and says "Their turn" (H-19). When the update allows nothing but passing and ending the turn (`TurnActions.idle`), it glows green (H-20): its slot (`.end-turn-slot`) draws a soft radial-gradient halo behind it that breathes by opacity (`end-turn-glow`). It is not a shadow: macOS WebKit clipped the tilted button's blurred shadows to a hard-edged box (19.76); with reduced motion the glow stays still. When it does not glow, a press asks first (V-46, 15.70): `EndTurnQuestion` opens in the `overlay` layer, through a portal to `body`, and lists `TurnActions.left` (Attack, Buy, Play loot, Use abilities). End turn, E or Enter confirms; Keep playing, Esc or a click outside closes it. A new update closes it too. The setting `no_end_turn_ask` (false by default, so old settings files ask) turns the question off. The button looks like the game's cut-out art: the game's hand-drawn letters, a thick ink outline, a lumpy tilted shape and a hard drop shadow that it sinks onto when pressed. Pass in the stack panel, Wait for my turn in the action bar, and the Buy and Attack icons share the ink outline and shadow. The letters come from `--font-game` in `style.css`: font-souls Title for Latin, then the Russian card font, which the browser uses glyph by glyph for Cyrillic, then the system font. `fonts.ts` registers both faces from `App.Fonts()` URLs; without the private images there are no URLs, no faces, and the system font shows. Keys (`useKey` in `keys.ts`, F-15): E ends the turn, Space passes, as the Pass button does. Keys pressed in a text field, a dialog, or a menu are left alone. Space also never clicks a focused button, so it cannot end the turn by accident.

Opponents (`OpponentArea`, 15.18) show the same facts: a small name outside the board (H-21), coins with the same `Coin`, the soul crystals, the character with its `stats` badges, the items, and the hand as fanned backs (F-07, F-08, H-17). At the top the area mirrors the own area: a three-column grid keeps the character centered over the board, and the hand row is shorter than its backs, so they hang past the top edge, upside down as across a real table. In a side column (`.player-left`, `.player-right`, 150 px) the name comes first, clear of the corner menu, then the hand and the cards at `small` size, two to a row. The narrow columns leave the board more width, so with three players, where the top is free, it grows (F-09). The allowance wraps only between its parts.

The coin by the cents is the game's own coin (15.38): `App.Icons` gives `assets/icons/coin.webp`, the ¢ face cut out of the game's `coin.png` by the tools repo, or no URL when the file is missing; the store keeps it in `store.icons`. `Coin` in `PlayerArea.tsx` draws it, and falls back to the drawn ¢ coin when there is none or it fails to load. A steal reuses it (15.75): a `stole` event names the victim in its text, and the `steal` effect flies a `Coin` from the victim's coin counter to the thief's, with "−N¢" on the first and "+N¢ stolen" on the second when it lands. A `stole` without a victim keeps the thief's popup alone. The Attack icon works the same way (15.24): `App.Icons` also gives `assets/icons/sword.webp`, the game's 65 px pixel sword (lossless WebP of `assets/sword.png`), drawn with `image-rendering: pixelated`; `SwordIcon` in `TurnActions.tsx` falls back to the drawn sword. Dim, the image is greyed and faded like the drawn icons.

Souls are a column of gem slots left of every character, like Hearthstone's mana crystals (`Souls` in `PlayerArea.tsx`, 15.39, V-30, V-31). `soulSlots` in `table.ts` gives one slot per soul the game needs, `GameView.win_souls`, with the gained ones (`PlayerView.souls`, the soul value) filled from the bottom up; souls past the target add filled slots. A view without `win_souls`, from an older server or record, counts four. The gems are pure CSS (`clip-path` rim and inset), so they look the same without the private images; `--crystal` sets their width, 16 px for the own area and 12 px for opponents. The character cell pads its right side as wide as the column, so the card stays centered. Gained soul cards are not on the table (15.56, V-43): the items row skips `Role.soul` cards (`isSoul`), and each filled crystal holds its card instead. `soulCards` in `table.ts` lists the card behind each filled crystal, bottom up: the character's own soul value first (`CardView.souls` on the character, R-CARD-35), then each soul card once per soul it is worth (`CardView.souls`, set by the engine's `soulsOf`; a view without it counts one). Hovering a filled crystal, or a long touch, zooms its card through `useZoom` in `Card.tsx`, the same hook every card uses. A soul's crystal carries the card's `data-zone` (`obj-N`) and `ui.object` handle, so an effect that picks or aims at the soul does it on the crystal; a highlighted crystal grows and glows in the card highlight's color. The character's own crystal has no zone: the character card keeps it.

Curses sit apart from the items (`Curses` in `PlayerArea.tsx`, 15.55, V-42): the items row skips `Role.curse` cards (`isCurse` in `table.ts`). In the own area and at the top they stand at the far left of the status cell (`.own-left`, `.opp-left`), pushed there by `margin-right: auto`, so the name and coins stay by the character and the crystals stay clear. In a side column `.opp-left` is `display: contents`, so the curses are a row of the column itself, above the character at its left. Without curses the group is not rendered, so no area changes size (V-23).

## Card backs

Face-down cards show their deck's back (V-26). `App.Backs` gives the loot, treasure and monster back URLs from `assets/backs/<kind>.webp`, or no URL when the file is missing; the store keeps them in `store.backs`. `Card` draws the back image, and falls back to the plain dark back with the deck name when there is none or it fails to load. An opponent's hand is `Pile.HiddenHand`: one loot back per card, fanned, at most eight, with the card count, in the `hand-<id>` zone, so drawn cards fly to it. A back never carries a card ref, so it cannot reveal the card. When the view sends an opponent's hand (a `StatRevealHand` static such as Guppy's Eye), `PlayerArea` draws `Pile.RevealedHand` instead: every card face up, in the same fan and zone, each zoomable on hover (19.5).

Effect durations scale with the animation setting (ST-05) and speed up when updates pile up; past 8 waiting updates they are skipped, so the table always catches up. Each effect has a time limit, so a closed screen never blocks playback.

## Cards

`Card` shows a card image, or a blank card with its text when the image is missing (A-11). Sizes: `hand`, `table`, `small`, `zoom`; everything inside scales with the width through container query units. Hover zooms a card; on touch a long press does (B-06). A mouse zoom ends when the pointer leaves the card, and also on the first pointer-over outside it: a part under the pointer that was redrawn, such as an image that failed and became the drawn face, sends no leave (19.50). The zoom keeps the hovered card's box (`Zoom.at`); `CardZoom` measures itself before it paints and `placeZoom` in `zoom.ts` puts it right beside that box, toward the window's middle, or, for a hand card (`rise`), centered over it on the bottom edge, always inside the window (15.27, F-16, T-27). A touch zoom stays centered. The card's footnotes (Eternal, Trinket, Curse, Guppy) show as keyword tips beside the zoom, on the side away from the card; the blank zoom face no longer repeats them. A card with an `objectId` pops in when it first appears and is a `data-zone` for effects. It stays still when an effect of the same update already brought it there, like a `fly` or a `place` (19.6, [Animations](Animations)).

## Player actions

`actions.ts` turns the update's allowed intents into what the table offers: buttons (pass), the turn actions (attack, buy, end turn), per-card actions (play, use an ability), a choice, or a discard. The table offers nothing else, so it never sends what the server would not allow; a refused intent still shows the engine's reason and rule ID.

* Cards the player may act on glow yellow; clicking or tapping one opens its action menu.
* A playable loot card can also be dragged onto the board (`data-drop="play"`). The drag is plain pointer events with pointer capture (`HandCard` in `PlayerArea.tsx`).
* Aiming (15.25): a click on a card whose one action asks for a target first starts aiming (`store.aiming`, set by `interact`); the next click picks the target. The targets come from the engine: `update.aims` gives the first target options of each allowed play or use, by its index in `allowed` (`Game.Aims` in `aims.go`), so the client computes no rules. While aiming, the targets glow red (`hl-aim`), a hand card stays lifted in the fan, and with a mouse a red arrow runs from the card's middle to the pointer (`AimLayer` in `Aim.tsx`, transform only; the head's tip is at the pointer, the shaft stops at its base). `AimLayer` takes the next click in the capture phase: `zonesAt` and `targetAt` in `aim.ts` find the target under it (a card's `data-zone`, a player area, or a stack row's `data-stack`); a target sends the play and keeps the target in `store.aimed`, and the target prompt that follows picks it at once (`aimedOption` in `actions.ts`). `aimClick` in `aim.ts` decides the click (15.33): the aiming card itself does nothing unless it may target itself, then it picks itself; empty space cancels; and any other card, pile, or stack row that is no target keeps aiming and shows the aim's `reason` from the engine (`targetReason` in `aims.go`) in a note above the click for 2.5 s. A player is aimed at by the character card only: it carries `data-player`, `zonesAt` turns that into `player-N` and leaves out the player areas' own zones, and `interact.character` lights the character instead of the area. A right click, Esc, or a new update cancels. Such cards are not dragged; a card with a mode or no target keeps the menu and the drag.
* Place, then aim (15.34): a card with a mode is dragged onto the board; its mode dialog asks first. The target prompt that follows is aimed, not asked in a dialog: the engine names the card in `view.activating` (only for the chooser), `promptAim` in `aim.ts` turns the prompt into an aim from it (`Aiming.choice` instead of `Aiming.intent`), and `GameScreen` starts it before paint, so the dialog never shows. A pick sends the prompt's option for that target; Esc, a right click, or empty space sends its cancel option (`cancelOption`), and the engine leaves the card in hand. The aim yields to `store.aimed` (a card already aimed at its target picks it at once) and to the dialog when a target or the card is not on the table (`onScreen`). While aiming, player areas offer no pick; the character card is the player's target. A card with no valid target is never offered: the engine refuses it (R-ABIL-06).
* The aiming arrow (15.32, `AimArrow` in `Aim.tsx`, styles in `Table.css`) follows Hearthstone's: a chain of thick red blocks from the card and a big notched head, a little see-through and drawn over everything. The chain is placed once with translate and rotate; `blocks` in `aim.ts` counts how many fit short of the head. The blocks march toward the head (`aim-march`); the first fades in and the last fades out in step, so the loop has no seam. Over a valid target (`targetAt` on every pointer move) the arrow gets `.on`, and a red ring with cross ticks marks the tip. Only `transform` and `opacity` move; the `--march` duration follows the animation speed (`scaleFor`), and speed off or reduced motion stands the arrow still. It is pure CSS, so it looks the same without the card images.
* Choices show as a dialog; card options show as cards (V-07). Options that point at the table (`view.options`, from the engine) glow blue there and can be clicked in place.
* A choice, a discard and an order share `ChoiceFrame` (`ChoiceDialog.tsx`, 15.29): a backdrop dims the whole table and takes its clicks, and the options are big cards (`Card` size `choice`) under the title (H-11). Its "View board" button swaps the window for a small bar at the bottom edge with the title and "Back to the choice" (F-20). Meanwhile the table answers as before: options on it glow and can be clicked. A new update remounts the frame (`key={game.step}`), so a new choice always opens in full.
* Others' aim and hover (15.36, ADR 016): `PresenceSender` in `Presence.tsx` tells the server what this player points at, as a `presence` message, only when `welcome.presence` is set. `presenceFor` in `presence.ts` decides what is shared: while aiming, the aiming card (`from`) and the spot under the pointer (`at`), or the pointer on the board frame (`point`, 0 to 1) when it is over no spot; on the player's own turn, the hovered spot alone; while waiting, nothing (owner, 2026-10-20). A card in the own hand always goes as its hand slot (`cardSpot`), never its object (A-16). The sender sends on a change, at most every 70 ms, and renews a still presence every 2 s; leaving the window or the table clears it. Received presences live in `store.presence` by seat and go when not renewed in 5 s, on an empty one, on a new table, or when the connection drops. `PresenceLayer` draws each other seat's presence: `spotElement` finds the spot on this screen (a hand slot is that seat's fanned back, the last one past the fan), the spot gets `data-presence="at"` (a red frame and glow) and an aiming hand slot `data-presence="from"` (the back lifts toward the board), and `AimArrow` with `others` runs from the source to the spot or the point. Others' arrows use the `presence` layer, under every window ([Layers](Layers)). A spot that is gone shows nothing.
* Why not (15.29, F-17, F-18, C-06): `update.blocked` says why each of the player's other cards and turn actions can't be used now (`Game.Blocked`, see [Rules engine](Rules-engine)). `actionsFor` maps it to `Actions.blocked` (object → reason) and `TurnActions.why`. `interact` gives a blocked card's handle a `why`; `Card` shows it under the card's zoom (`card-zoom-why`) and, on a click, in the note where the player clicked. Buy, Attack and an own-turn End turn that are dim but have a reason stay clickable (`aria-disabled`, not `disabled`), say it in their tooltip, and show the same note on a click. The note is one for the whole table (`store.why`, `WhyNote` in `Why.tsx`): the aim's wrong-click reason uses it too. It fades after 2.5 s; a new click shows it again.
* A deck attack's drawn card waits for its slot in `view.revealed` (19.9, R-ATK-08); every viewer gets it. The board shows it face up on the monster deck (`Deck`'s `top`), and the slot dialog shows it as its `subject`, so a player who missed the large reveal still knows the card. The deck hides it once a `place` effect flies it to the slot.
* A question about one card (Cain's Eye: "Put the top card on the bottom?") names it in `view.subject` (19.11), only for the chooser; the engine's `Question.Subject` sets it. The dialog shows it as its `subject`; option labels name it as a card value, by its title (16.4).
* A look (V-07) shows the cards of the update's `looked_at` events for this player in `LookDialog` (`ChoiceDialog.tsx`), until OK. * Every roll waits for its roller's throw (15.61, ADR 014): a throw prompt whose `text` names the roll. `actionsFor` turns the allowed throw into `Actions.throw`. `Throw.tsx` draws it in the middle of the screen, where the dice effect lands: the roller gets a big glowing Throw button holding their die (Space presses it); everyone else sees the die shaking (`throw-shake`) and "Ann is throwing…". * Before turn 1 the view has `first_roll` (15.43, UC-26). The turn badge says "Before turn 1 · First player roll"; no seat is active and no turn buttons show; `activity` says nothing. The stack panel lists the round's players (`FirstRollList`, `firstRollRows`): each die once thrown, in its roller's look, "throwing…" for the next. After a tie its title says so. A tie and the winner are long banners (`tieText`, `firstPlayerText` in `dice.ts`); the history keeps every die, the tie and "Bo goes first — rolled 1".

It is reset with the history.

* The player acts only on the latest update (`store.behind`) and once per step (`store.sent`); meanwhile buttons stay but are disabled, so nothing blinks.
* A card with two or more activated abilities opens the ability dialog instead of the menu (`AbilityDialog` in `ActionMenu.tsx`, C-05): the card large at the left, one button per ability line at the right. An index can point at another card's ability (copied tap abilities), so the client cannot read the lines from its own card data. Each line looks like a row of card text: parchment with an ink outline, the cost icon boxed at the left (a drawn tap arrow, or "$"), the cost in red ink, then the effect (`abilityLine` in `cards.ts` splits the words at the first colon). The same look asks a "choose one-" card's mode (15.58): `CardDialog.tsx` draws both, and `ModeDialog` in `ChoiceDialog.tsx` fills it from `view.subject` (the card) and `view.modes` (every mode, greyed without a valid target, `modeLines` in `actions.ts`). Dialogs use the game's letters: titles in `--font-game`, card text and option buttons in `--font-card`, font-souls Body from `App.Fonts().body`.
* On own turn the Buy and Attack icons carry a small paper badge with the purchases and attacks left (`TurnActions`' `left`, from `PlayerView.purchases` and `attacks`); it turns dark at 0. Attack-readiness marks (a green frame, "zzz", T-11, H-22) were tried and dropped: they do not suit this game (owner, 15.24).

## Stack and waiting

`stack.ts` has the words: `stackParts` describes a stack item in parts that keep the player, the target and the card apart ("Ann plays A Dime!!", "Attack: Bo rolls 4 against Gaper", "Bo deals 2 damage to Gaper"; damage a player takes names its card, "Boom Fly deals 1 damage to Ann", ADR 011); `stackLine` joins them into plain text. `stackIcon` picks a row's icon and `stackCard` the card it shows on hover.

The stack panel (`StackPanel.tsx`, 15.21) always sits in the board's info column, newest item on top; an empty stack says "Nothing on the stack". Each row is a square icon (cropped card art, a die with the roll, a blood drop with the damage, or a skull) and one line, with players in their seat color (`playerColor` in `table.ts`, also the dot by each name) and targets in red. Hovering a row, or tapping it, shows the card large through the shared zoom with a caption: the used ability's words, highlighted, and the owner. The words come from the engine view: `GameView` fills each stack item's `text` with the ability's text, or the chosen mode's; the game state never holds it. Highlighting on the card image itself is not possible, since the image has no map of its abilities. Pass sits in the panel header; Space presses it. An open attack or buy is no stack item (R-ATK-02, R-SHOP-02), but the panel shows it as a top row (15.91, V-51): `declaration` in `stack.ts` reads the public `view.attack` and `view.buying`, and `DeclaredRow` draws it without an icon, with a dashed edge. The engine buys the chosen item at once, so a buy row never names an item. A declared end of turn gets the same row, "Ann ends the turn" (19.74): `turn.end_declared` while `turn.step` is still the action step, so it also covers a card that ends the turn early; it goes when the end phase starts. A death end (`death_end`) is not declared and has no row.

The prompt banner (15.28, V-20) sits on top of the action bar, bottom right. `prompt.ts` has its words: `promptBanner` turns the open prompt into a title and a hint. To the asked player it says what to do: "Your turn" with what is left ("Play a card, attack, buy, or end the turn", from `Actions`), "Respond, or pass" with the stack's top line, "You may act", the choice's question, "Discard 1 loot card", or "Throw the dice" with the roll's label. Everyone else reads "Waiting for Ann", the name in her seat color, and the same words as the hint. The player's own aim (15.25) is a prompt too: "Choose a target", for which card, and that Esc cancels it. The asked player's banner is a gold plate in the game's letters whose glow breathes (`prompt-glow`); the others' is a dark plate. `stackPrompt` repeats any prompt other than priority as the stack panel's line ("Choose a target", "Ann: Discard 2 loot cards"); priority keeps its "Waiting for" and "Passed" lines. Pass glows the same way when passing answers the prompt.

The banner sits at the edge, so the table says it too (15.95, V-52). While the game waits for the viewer, the board in the middle glows green: `myMove` in `prompt.ts` is true for any prompt that asks them, on their turn or out of it, but not while they aim or pick a target, where only the answers glow. `GameScreen` adds that the player can act now and the game is not paused, and `Board` gets the class `my-move`. The halo comes 150 ms late, so a prompt answered at once shows no flash; it pulses once and then stays soft (`board-my-move`). There is no glow for "waiting for someone else": green and yellow look alike to many color-blind players. Instead `askedSeat` names the player the game waits for, and every screen draws a small hourglass in that player's color by their name (`Hourglass` in `PlayerArea`).

The active player's seat says what they do now, for everyone else (15.30, V-21): "Ann is thinking", "Ann attacks Pooter". `activity` in `prompt.ts` builds the line from public state only, as `LinePart`s that `PlayerArea` draws with the stack's `Part`, so names keep their seat color and targets their red. In order: the active player's own loot card or ability on top of the stack ("plays", "uses"), the death penalty, the attack from `view.attack` ("declares an attack", "attacks the monster deck", "attacks Pooter", or a player by name), a declared purchase from `view.buying` ("is buying"), and "is thinking" while any prompt waits for them. While the game waits for someone else with none of these, there is no line. The viewer's own seat never shows it; their banner says what to do.

A fight is framed red on every screen (15.31, F-19): `fighters` in `prompt.ts` gives the active player's character and the target from `view.attack`, once there is one, and `Card` adds the class `fight` to those objects. Another player's loot card shows large twice (H-10, T-16). First the `played` effect pops it in the middle with "Ann plays" when its `loot_played` event plays; it claims the card's `show` (ADR 012). Then `PlayedCard` (`StackPanel.tsx`) keeps the newest such card from the stack (`playedCard` in `stack.ts`) under the stack panel, as large as the info column allows. The view changes only after an update's effects, so the card is still there while its own resolution plays. The viewer's own plays get neither.

A loot card's path is shown end to end (15.74). The `played` effect starts on the player's `hand-<id>` zone and ends shrinking into the stack panel (`data-zone="stack"`). When the card leaves the stack, resolved or cancelled, the engine emits `discarded` with `text: "stack"` and `prev` set to its object on the stack. Its `fly` starts at `played-<prev>`, the `PlayedCard` figure (from its card, at its size), else at the stack row `stack-src-<prev>`. `PlayedCard` hides while that fly plays, so the card is seen once. The fly's `leaves` names the item's source; the store keeps it in `left` until the next view is shown, so the large card and the stack row stay hidden while the update's later effects play (19.41).

Rows of the stack panel and tiles of the history strip move (15.51, V-39). `Rows` and `Row` in `Rows.tsx` wrap them in motion's `AnimatePresence`: a new row fades in, the others slide to their place (`layout="position"`), and a leaving row fades out before the rest close the gap. Rows keep stable keys (`stackRows` in `stack.ts`, `stripEntries` in `history.ts`), so React moves them instead of drawing them again. A leaving row drops `data-zone` and `data-stack` and is `aria-hidden`, so no effect starts on it and tests skip it. Times follow the animation speed (`scaleFor`); with animations off there is no `AnimatePresence` and rows change at once. In one update, the damage and deaths a loot card dealt play before its discard flight (`marksFirst` in `playback.ts`), so the shots come from the card. Today the engine puts that damage on the stack, so it comes in a later update anyway.

While the player picks a target on the table (`picking`: an aim, or a choice with an option on the table), the main element gets the class `picking`: cards that answer glow (`hl-pick`, `hl-aim`) and every other card on the board and in the player areas dims (`Card.css`). While aiming, `interact` lights only the targets and the aiming card itself.

The banner shows the response timer from `update.deadline` (N-07); on another player's turn the action bar offers "Wait for my turn" / "Cancel wait" (`waitTurn` in `stack.ts`, N-16); the server does the passing. It is hidden once the turn before the viewer's is ending, since that end window is the last chance to act. The server also ends the wait when another player targets the viewer or their cards (15.84). There is no "Skip all" any more (15.84).

## Info panels

`history.ts` builds the history from the events this viewer received: one line per play, under turn lines (15.88, V-51). `historyKinds` lists every engine event kind: `line` gives a line, any other text says why it gives none. `history.test.ts` reads the engine's `pkg/rules_engine/testdata/event_kinds.txt` and fails on a kind missing from the table; after adding a kind in Go, run `go test -run EventKinds -update-event-kinds` there and give the kind a row. A bought item comes as `purchased` and also as a gain; the buy line names it once. An item that died as an attackable item and was destroyed also gets one line. Entries of a play, an ability, a buy and a kill are `headline`s, for the strip (15.89). An attack's target line is not: the attack roll's tile names the monster. A played loot card and a used ability get no line of their own (`loot_played`, `activated`): the resolved line tells the result. 17.6 gave them one for a row button; 17.7 removed it again, and the Undo button names the play instead. Every death resolves a death stack item first; the death event then turns that entry into the kill ("Bo kills Gaper"), with the dead card and `badge: 'kill'`, so the strip and the History name it once. A buy gets `badge: 'buy'`. For the strip's popout (15.90) a headline has `from`, the card shown large, and `outcome`, its results: the target of a card's item, a damage's target with the number (the dealer is its card, else its player), a kill's dead card, a buy's item. The lines after a headline in the same update add their cents, loots, items and souls; a new update starts with none. `CardZoom` draws them after an arrow (`Outcomes`), with the 15.37 starburst (`starPolygon`) or a skull. The server already filters events per viewer, so a hidden loot reads "Bo loots a card". The history lives in `store.history`, grows as playback shows updates, and is lost on leaving the table (replays come in step 10). A resolved stack item without a card (a roll, damage, a death, a death step, a penalty) takes the strip's words from `stackLine`, so both views say the same (19.52); `entriesFor` gets the update's view for them. A roll's `stack_resolved` carries the die as rolled; the `roll_resolved` right after it carries the result after roll changes (Polycephalus's -2, 19.1). When they differ, the entry reads "rolls 6 → 4" and its strip item gets the result as its `roll`.

The history strip (`HistoryStrip.tsx`, 15.22, 15.89) is the board's first column: one icon per headline, newest on top. A buy or a kill shows its card with a coin or skull badge, and its history line under the zoomed card. Any other headline is a resolved stack item, drawn by the stack panel's `ItemIcon`. The engine's `stack_resolved` event carries the resolved `item`, with its ability's words, so the strip knows its kind and whether it was an attack; `stackBadge` puts a sword on attacks and a bolt on loot plays (H-08). Hovering an icon uses the stack's `itemZoom`. A gold line ends each turn's run of icons. Stack items carry `source_card` and `target_card` from the engine (views and the resolved event fill them while the card is public), so an attack roll names and shows its monster even after it died; an item without ability words shows its line under the zoomed card instead. The engine splits roll texts: a roll result trigger's `text` is only the rolled line (`rollResultText`), and the item that rolls says only the words up to the roll (`rollStartText`, "Roll."), on the stack and in the history; the zoomed card, image or text, shows every result. The scroll button on top opens the full `HistoryPanel` in the info column, under the stack; it starts hidden.

Rollback (ADR 020, 17.3): each entry keeps `step`, the first step of the update that brought it (the update shown before, plus one). In a game with a rollback mode (`update.rollback_mode`) the History panel has one Undo button under its title (17.7, `UndoButton` in `InfoPanels.tsx`); Disabled mode shows none. `undoButton` in `history.ts` decides it: its target is the last step of `update.rollback_steps`, which the server sends in Godmode and Soft, and a press sends `rollback` with it. Each press undoes one move; press again to go further back. The server leaves a play's answers out of the targets (a mode, a target, a copied ability), so a play that asked a target is undone by one press. The tooltip names the move: `store.moves` keeps one `Move` per update (`moveOf`: its steps, a name, and the first barrier it holds); a play is named by its `loot_played` or `activated` event, "Bo plays A Penny!", an ended turn by its end, anything else by its first history line. `moveText` names a target by the moves from its step up to the target's `last`: a play that asks a target gets its event with the answer, and the server marks the answer's step as `last` (17.8). A target with no line there, such as a trigger order or Bum Friend's put-back pick, reads "Undo: Bo's choice" ("your choice" for the viewer's own); it never borrows the next move's name. The button is greyed (`aria-disabled`, so a click still shows the reason in the `WhyNote`, 15.29) for a spectator, at the game end, while a vote is open, while the game is paused, and when no target is left: "Nothing to undo since a die was rolled" names the barrier from the move that holds step `rollback_from − 1` (Soft), "since the server restarted" for a cut, else "Nothing to undo yet". While the viewer's own action waits for its update, it is plainly disabled. A choice window covers the History like the rest of the table; "View board" uncovers it. An update with `rollback` greys every entry from the target step on (`undone`) and adds a row "Bo rolls back 3 steps" (`rolledBack`); the strip greys its undone tiles too. Playback plays no effects for it, and `store.jumped` holds the table's own animations (`viewScale`: a card's pop-in, effect icons, moving rows) until the next update, so the table jumps to the restored view (item 8.5). The last roll, a look, an aim and an open menu go with it.

Soft (17.4): when the latest target is the viewer's own move, the button reads "Ask to undo" and sends `rollback` with `ask`; the other players' "Undo" opens the vote. While `update.rollback_vote` is set, the Undo button is greyed, the table offers no actions, the action bar says "Rollback vote", and `RollbackVotePanel` (layer `vote`) shows the vote at the top: the voters answer Yes or No, whoever opened it may cancel, the rest see the tally. A `rollback_end` adds a history row ("The rollback was declined"). The vote names the move by `moveText`, as the Undo button does. The host screen's Detailed setup picks the mode, Disabled by default, with a hint per mode; the host settings remember it.

A server restart (17.5): the app keeps its history over the reconnect. If the restart cut the rollback history, every update carries `rollback_cut`, and `restartCut` adds one row "The server restarted; no rollback before this" (`restarted`) for each cut it has not shown; nothing before it is a target, since `rollback_from` is past it. An app that restarted itself has no old rows, so the row is its first.

The turn badge shows the turn number, the active player and the step. Player areas show what the engine computed: HP, ATK, cents, souls, hand size, and for the active player the loot plays, attacks and purchases left (`PlayerView.loot_plays`, `attacks`, `purchases`). Every number on a card is a `Badge` in `Card.tsx`: an SVG shape with a thick ink outline, a hard shadow and a slight tilt, and the number in the game's font (`--font-game`), like the End turn button. Health is a red heart, the dice a bone-white die, attack a gold blob. Card counters are a green blob on the card art (`CardView.counters`, C-01); a text card has it in its top corner, clear of the words. A monster's `CardView.stats` holds its live and printed health, dice and attack; `Card`'s `monster` draws a badge only for a value that differs from the print (C-03). A stat above its print gets a green number, below it a red one (`trend` in `stats.ts`, 15.92); hurt health keeps its pale heart and red number. The view's `sources` (15.54) say why: `statLines` builds the sums the zoom shows under the card (`Zoom.stats`, `card-zoom-stats`), lasting sources first, then roll changes. `tempSources` picks the effects of this turn and the next-roll boosts, one icon per source (`SourceIcons`, `card-sources` on the right edge, below the name); each icon is cut from its card's art, a text card shows its initial, a hidden source a "?". Icons take the pointer, unlike the badges: hovering one zooms its card with what it does, and leaving it for the card zooms the card again. Lasting sources get no icon (owner, 2026-10-22). Icons come and go in an `AnimatePresence` (`source-icon`, 15.93): a new one fades in, a used next-roll icon pops and fades, an icon of this turn shrinks away when the turn ends; a leaving icon takes no pointer. With animations off they change at once. The badges follow the view at once; they do not wait for the fade. An aimed attack's row in the stack panel has a second line from `view.attack.odds` (`attackOdds` in `stack.ts`, `oddsLine` and `hitsText` in `stats.ts`, 15.94): "Hits on 4+ (DC 5 − 1 Meat!) · ATK 1 = …"; roll changes are taken off the DC. A thrown roll's row adds `rollChanges` and its result from the item's `sources` and `final`; the History adds the roll event's `sources` to "rolls 1 → 2". The health badge replaces the damage mark on monsters and characters; a card without health keeps the dark-red mark in its top corner. The zoomed card shows no badges, so its words stay readable (owner, 15.23). A card that keeps a die number (Telepathy for Dummies' stored roll, Red Candle's or Crystal Ball's chosen number) gets a die per number on its art, in its owner's dice look (`CardView.dice`, from the engine's `CardDef.Dice`; 15.67).

## Pause, reconnect, game over

* A lost connection during a game keeps the table (`lobby.lost`); `LostOverlay` offers Reconnect, which says hello again with the seat's token from `welcome`.
* The seat token also goes into the settings (`settings.rejoin`: address, token, game) whenever the player sits at a table. A restarted app sends it on the next connect to that address and lands back in its seat; `seatOf` then reads the seat from the welcome.
* The menu offers that seat (15.99, M-05). `settings.rejoin.via` keeps the path it was joined by. On every menu visit `checkRejoin` asks the server's `/seat` through `App.CheckSeat` (Go, `servers.go`), at `httpBases(address)`: the same order as `wsURLs`. A live seat sets `rejoinable`; the menu shows "Rejoin: Ann's game · LAN" in its top corner, not in the centred menu, so nothing moves when the answer comes (19.49). A dead seat is forgotten; no answer keeps it. `forgetSeat` also runs when an update says the game is over, on a game-ending notice, on `leaveTable`, and on `quit` while seated. `endedGame` keeps the game id for the record download after that.
* The LAN screen (15.97) also takes a seat back: a started game in `lanRows` whose id is `settings.rejoin.game` offers Rejoin, and `joinServer(address, { token })` sends that token, whatever address the game was joined by. Any other started or full game shows with Join off.
* Recent servers (N-18): `settings.recent` keeps each joined server's address and the `name` from its welcome, newest first, five at most. `joinServer` saves the address with `remember`; the welcome's name follows through `renamed`, after that save, so neither save undoes the other. The Online screen shows `serverLabel` (the name, else the address) with the address as its tooltip, and an × that calls `forgetServer`. The Games list shows `welcome.name` under its heading. Go reads an old settings file whose `recent` holds bare addresses.
* Recent servers show live status (15.100, M-04). `OnlineConnect` calls `checkRecent` when it opens and when the Recent addresses change. It clears `recentStatus`, then asks every server at once through `App.ServerStatus` (Go, `servers.go`, the server's `/status`) at `httpBases(address)`. Each answer sets its address to `{ open }`, or `'down'` when no base answered, so the rows show at once and fill in one by one. `statusRound` drops a late answer of an older check. `upText` is the row's text: "Checking…", "Down", or "2 open games"; a dot before it is green when up and red when down.
* `update.pause` shows `PauseOverlay` to the others: who is away, the votes, and Wait / Go on without them (`vote` messages).
* `view.over` shows `EndOverlay`: the winner and Save record. `App.SaveRecord` (Go, `record.go`) asks where to save and downloads `http://<server>/record?game=…&token=…`; it accepts only such links.

## Save and continue

The in-game **Menu** (`GameMenu`) offers **Save and leave** to seat 1, the host (`save` message), and **Leave game** to all. After `saved`, everyone is back on the server's game list. **Continue a saved game** on the host screen starts the in-app server and shows that list (`store.hostSaved`); **Continue** sends `load`. A loaded table shows its seats as "back" or "not back yet".

## Menu screens

The splash, the main menu and the menu-like screens (`src/screens/`) use the game's letters too (15.40, V-33). Titles and screen headings use `--font-title` from `style.css`: the Russian card font (tboi4s), which has mixed case for Latin and Cyrillic, then the system font. Buttons use `--font-game`, as on the table. Body text, form labels, inputs and the fan-game notice stay in the system font, so they read easily. Headings keep `font-weight: bold` with `font-synthesis: none`: the game font has no bold face and is not faked, while the system font fallback stays bold, as it was before the change. Buttons off the table share the look of the ability lines (15.24): cut-out parchment (`--paper` in `style.css`) with an ink outline, a hard shadow and a slight tilt that alternates; the main action of a screen (`.primary`) is the gold of End turn (`--gold`). One rule in `style.css` covers `.screen button`, `.menu-buttons button`, `.overlay-buttons button` and `.game-menu-button`. Inputs and selects are parchment slips with an ink arrow; checkboxes are parchment boxes with an ink tick.

The main menu's title is the foursouls.ru banner (15.41, V-34): `App.Icons` gives `assets/banner.webp`, the site's Four Souls logo, downloaded by the tools repo (`scraper banner`). `Title` in `MainMenu.tsx` shows it inside the `h1`, with alt text "Four Souls", so the heading keeps its name. Without the private images, or when the image fails to load, it shows the text title as before. The text title also shows until the banner has loaded, then the banner replaces it once: the menu is centred, and a title that changed size after it showed moved the buttons under the pointer (19.49). The banner is at most 526 px wide (the site's size) and 40% of the window high.

The last main menu button is Exit (15.79, M-02): `quitApp` in the bridge calls the Wails runtime's `Quit`, which closes the window and runs the app's shutdown, as the window's close button does. The fake bridge records the call in `window.fakeQuit` for the e2e tests.

The main menu starts by where you play (15.96, M-03, M-06): Play, Records, Settings, Exit. Play opens its group in place, indented under it: LAN, Online and Learn to play. A second click on Play or Esc closes it; `playOpen` in the store keeps it open while the player is on its screens, so Back finds it open. The menu is centred, so a menu that grew would move Play and the title up; `useOpenHeight` gives the `nav` the height it has with the group open, always, so nothing above Play moves and Exit stays on screen in the default window. The group overflows into that room as it grows (`menu-group` in [Animations](Animations)); `contain: inline-size` keeps it from widening the buttons. Features still to come, Learn to play and Records, are disabled with a "Soon" badge (`Soon`, M-07); their accessible names end in "(soon)".

LAN and Online set `store.path` and open the join screen (`openPath`); `JoinScreen` shows `LanConnect` or the Online screen, and the server's Games list once connected. Back and Esc go one level up (`useEscape` in `keys.ts`): the Games list to its join screen (`quit('join')`), the host setup to the join screen, a join screen to the menu. The LAN screen (15.97, M-03) has Host a game on top, then the games `findLanGames` finds; `useLanSearch` searches again 2 s after each search ends, while the screen shows, so a new game shows up by itself. Its address field starts from `settings.lan_address`, the address last typed there and connected to; LAN joins pass `recent: false`, so they never fill Recent. The Online screen (15.98, `OnlineConnect`) has the nickname, a server address that starts from the newest Recent entry, Connect and Recent; it lists no LAN games. The host screen still decides by the connection, not the path: connected to a server that this app does not run, it creates the game there; a dedicated server joined from LAN by address does that too.

The menu screens drift on the foursouls.ru night sky (15.42, V-35). The tools repo downloads the site's own layers (`scraper background`): a sky tile and five see-through star layers, 600×400 each. `App.Icons` gives their URLs in `sky`, all six or none. `Sky.tsx` draws one fixed layer per tile under every screen but the splash and the game table (`onSky` in `sky.ts`), on the `sky` layer at the bottom of the window ([Layers](Layers)). The logic is the site's: in a 120 s loop the sky moves one tile down and to the left, and the star layers 4, 6, 8, 10 and 12 tiles, so the nearer stars move faster and the loop has no seam. Here each layer is one tile larger than the window and slides by exactly one tile in its own share of the loop (`sky-drift`, [Animations](Animations)); only `transform` moves, so the window is not repainted on every frame. The sky is drawn at twice its size, as on the site. The animation speed setting scales the loop; Off, or a system that asks for reduced motion, stands it still.

The app has one theme, dark (15.80, ST-07). The colors are the `:root` tokens in `style.css`; there is no theme setting and no `data-theme` attribute. An older settings file's `theme` is ignored by Go and dropped on the next save.

## Languages

Texts come from `t(key, values)` in `i18n.ts` (ADR 021). Keys are typed from `src/locales/en.json`, so a typo fails `tsc`; each line there has its `text` and a `note` for translators. Every other file in `src/locales/` named by a language code (`ru.json`) is a language, found by Vite's `import.meta.glob`; it holds texts only. Lookup goes the chosen language, then English, then the key itself. `{name}` placeholders take the values; a plural line has one text per CLDR form, picked by `Intl.PluralRules` from the value `n`.

The `language` setting is kept by Go with the others (`internal/settings`, checked only as a two- or three-letter code). `''` follows the OS: `navigator.language` if it is listed, else English. The list (`languageList` in `locale.ts`) is English, every language file, and every language the cards have names in, each in its own name from `Intl.DisplayNames`. The card languages come from the `names` Go sends with `App.Cards` (`cardLanguagesOf`, 16.10); no extra binding. Until the cards load the list has the files only: `loadCards` calls `setCardLanguages`, which resolves the saved setting again (a saved card-only language like Russian shows then) and puts the new list into the store's `languages`, which the Settings screen reads. A card-only language has English screens and its card names. The store calls `setLanguage` when settings load or save; `App` subscribes to the setting, so every screen draws again in the new language at once. The fake bridge's `?cardlang=xx` names Isaac in `xx`, so e2e checks a card-only language without touching the card files.

The test language `qps` is built at run time from English (`pseudo`): `Join` becomes `[!! Ĵôîñ ~~ !!]`. It is listed only in development builds (`import.meta.env.DEV`: Vite dev, `wails dev`, the e2e tests); a release build that reads a saved `qps` follows the OS. `make screenshots LOCALE=qps` starts every fake page in it (`VITE_LOCALE`) and saves into `.cache/screenshots/qps/`; e2e tests find translated text with `tr(key)` from `e2e/tests/locale.ts`, which gives the line in that language. Plain English on a `qps` screenshot is a string not moved to `en.json` yet.

Every text the client writes comes from `en.json` (16.3): screens, menus, table, dialogs, tooltips, screen-reader names, and the history, stack and stat lines built in `history.ts`, `stack.ts` and `stats.ts`. Text the server sends comes as messages, a key and values (16.4): refusal reasons, prompt questions, choice options, roll and stack labels, errors. `say(msg, names)` in `i18n.ts` shows one in the chosen language, a card value by its name and a player by theirs; a key missing everywhere shows as the key. `actionsFor`, the banner, the stack, the dice and the history call it; `errorText` shows a server error's `text`, and `messageOf` reads a Go error that is a message as JSON (nickname, setting, LAN, hosting), as `deckRatiosText` does the host screen's deck ratio reason. Still English: an ability's and a mode's words (card data, sent as `{text}`), a counter's kind name, Go's OS and network errors, player names, dice look names, mat names Go takes from image files, the dev-only card gallery, and the splash's fan-game notice (legal text, `internal/legal`), which stays as written. `locales/server-keys.json` lists every key the server sends (written by a Go test); `i18n.test.ts` counts them as used. The two-language e2e test (`languages.spec.ts`) plays one game with one page in English and one in `qps`.

Card names follow the language too (16.5). `App.Cards` sends each card's `names` and `translators` in every language card_db has; the store keeps each card's `name` in the chosen language (`inLanguage` in `cards.ts`, English if missing) and renames the cards when settings load or save. Everything that names a card reads that `name` from the store: text-only cards, the zoom, history, stack and stat lines, server messages' `{card}` values, choice options and tooltips. The zoom credits the shown language's translators under the card (`translatorsOf`, CD-06); English credits none. Card texts stay English for now. Images follow the language too (16.6): `App.Cards` sends `images`, one URL per language folder of the private images, and `inLanguage` sets the card's `image` to the chosen language's, else English's. Saving the setting swaps the images at once, as it does the names. No language but English has card images yet. The fake bridge reads names and translators from `b2.json`, so `make screenshots LOCALE=ru` shows Russian card names on English screens; its real cards have English images only, and its Isaac has a Russian test image for `cards.spec.ts`.

A line that names players or cards in their colors is split at its placeholders by `partsOf` in `stack.ts`: `t('stack.loot')` gives `{player} plays {card}`, and each `{name}` becomes its colored part. A line with "You" has two keys, `.you` and `.other` (`history.loot.you`, `history.loot.other`), so a language can bend the verb.

To add a UI string:

1. Add a key to `src/locales/en.json`, in its sorted place: the area first (`lobby.`, `table.`, `history.`, …), then lower-case words joined by `_`.
2. Give it a `note`: where it shows and what each `{value}` is. A line with a count uses plural forms with the value `n`: `{ "one": "{n} card", "other": "{n} cards" }`.
3. Show it with `t('area.key', { values })`. The key is a string literal; to pick among keys, pick among `t()` calls (`switch`, `?:`), never build a key.
4. Find it in e2e tests with `tr(key, values)`, or `trRe(key, values)` for a pattern ([Frontend tests](Frontend-tests)).

`make lint` fails on letters in JSX text, in the text attributes (`title`, `aria-label`, `placeholder`, `alt`, `label`), and in strings or templates shown as JSX children (`no-restricted-syntax` in `eslint.config.js`). `i18n.test.ts` fails on a key used in code but missing from `en.json`, on a key no code uses (or `locales/server-keys.json` lists, 16.4), and on a `t()` call whose key is not a literal.

## Translation checks

`make i18n` checks the translations (16.7, ADR 021 items 10 and 16). The checks are pure functions in `locale.ts` (`checkLanguage`, `todoOf`, `mergeDone`), tested on test tables in `locale.test.ts`; `translations.test.ts` runs them on the real files under Vitest, reading and writing them through `node:fs` (declared in `src/node-fs.d.ts`, since the frontend has no `@types/node`).

* Without `LOCALE` (and in `make lint` and `make frontend`): every language file has no stray key, no wrong shape (one text where English has plural forms, a plural form the language does not have, a copied `{text, note}`) and the same `{placeholders}` as English; `i18n.test.ts` adds unused and missing keys of `en.json`.
* `make i18n LOCALE=xx`: also every key missing and every plural form the language needs, those `Intl.PluralRules` picks for whole numbers 0–1000 (`requiredForms`: Russian `one`, `few`, `many`). Placeholders are compared per key, all forms together, so one form may leave out `{n}`. It prints one line per gap and fails while any is left.
* It writes `.cache/translations/xx/todo.json` for agents: a `how` list, each form's example numbers, the glossary notes, and the gaps grouped by area, each with key, English, note, placeholders, forms, the glossary terms its English uses with this language's word, and the wrong text (`now`). `AREA=lobby` keeps one area, in the list too.
* An agent writes only `.cache/translations/xx/done.json` (key → text); the next `make i18n LOCALE=xx` merges it into `xx.json`, sorted by key, deletes it, and leaves out keys `en.json` lacks. A key set to `null` there is deleted: `todo.json` lists stray keys under `stray` for that.
* Every file a run reads must be JSON first (16.11): without `LOCALE` every language and glossary file, with it `xx.json`, `glossary/xx.json` and `done.json`. A broken one fails the test `every file make i18n reads > is JSON` with `file:line:column`, the line with a caret, and a hint; the other checks are skipped, so a merge never writes over a file it could not read. `jsonError.ts` finds the place with a small scan of its own (`jsonErrorAt`), since `JSON.parse` words its errors differently per Node version and names no position for some; `explainJson` gives the hint. `pkg/card_db` has the same hints in Go (`jsonerr.go`).
* The app imports the language files through Vite's JSON plugin. A broken file fails `wails dev`, `vite build` and Vitest's `i18n.test.ts` with Vite's own `Failed to parse JSON file` error, which names the file, line and column and shows the code around it; that is clear enough, so the app adds nothing.

The glossary lives in `src/locales/glossary/`: `en.json` lists each game term with a note, `<lang>.json` gives its word. Terms are matched in English as whole words, plural or not; they are context only, with no check of the translated words. `i18n.ts` loads `locales/*.json` only, so the glossary folder is no language, and `languageOfFile` skips `server-keys.json`. `LOCALE=en` and `LOCALE=qps` fail: English is the source and `qps` has no file.
